# 插件 0.3.11：好感曲线 x 轴 + 手动编辑被「拉回」的根因修复（2026-10-02）

## 结论

两件事一起做：
1. 博士反馈「手动编辑好感度，聊几轮又变回原来的值」——根因是**历史消息里残留着旧的 `%%FAV%%` 状态行**，模型照抄旧数值覆盖了手动值。已修。
2. 好感曲线补 x 轴（A+B+C）。

## 问题一：手改好感度被拉回（根因 + 修法）

**现象**：页签里把某人好感度改掉，聊几轮后弹回原值。

**排查**（逐项排除）：
- 编辑键与运行时键是否不一致 → 否。`favour.json` 里键是纯 QQ（`2681711819`、`2664648140`），`session_based` 关闭，
  页签 `set_state_by_key` 与运行时 `get(uid, scope=None)` 用的是同一个键。
- store 实例是否两份 → 否，同一实例。
- 查会话库 `data_v4.db` 的 `conversations.content`：**命中 `%%FAV%%` 残留**——
  - conversation `1d6319e4…`：msg 65 / 75 / 83 是 `%%FAV%% 2|…`、`2|…`、`3|…`，msg 73 是 think 里的
    “I need to remember to include the %%FAV%% status line.”，共 4 处；
  - conversation `f5da265f…`：msg 1 是 `%%FAV%% 1 | 友善 | 陌生人`，1 处。

**根因**：`collect_favour` 只把状态行从**发送文本**里剥掉（`resp.completion_text = cleaned`），**没有回写会话历史**。
于是每轮历史里都带着上几轮的旧状态行；模型看到自己前面写的是 `2`/`3`，就顺着写回旧值，手动改的数值被覆盖。
（这正是此前记在案上的遗留项「会话库中模型输出的 `%%FAV%%` 整行仍保留」的实际危害。）

**修法**（两层）：
- 拦截上下文：`inject_favour` 开头调用新增的 `sanitize_contexts(req.contexts)`，就地清掉历史里所有含标记的**行**
  （只删行不删消息；支持 `content` 为 str / list[dict] / list[ContentPart] / 裸字符串四种形态；幂等）。
  **不动 system_prompt**——注入文本里的指令行本身就含标记，清了就等于关掉功能。
- 收紧指令：`build_injection` 末尾追加「本段数值是唯一权威的当前状态。上面历史消息里若出现过状态行，那是过期记录，
  一律作废，不得沿用其中的数字。」

**副作用（正向）**：历史里少掉每轮一行状态行，顺带省上下文 token。

**真机验证**：拿容器内插件代码 + 真实 `conversations` 跑清洗——
`conv 1d6319e4…: marker 4 -> 0`、`conv f5da265f…: marker 1 -> 0`，合计 5 处。
离线自测见 `scripts/test_favour_sanitize.py`（覆盖四种 content 形态、幂等、非 list 输入）。

## 问题二：好感曲线 x 轴

原状：只画了 y 轴刻度（100/50/0/-50/-100），横轴空白；横轴是**按索引等距**排点（`toX = i/(n-1)`），
不是时间比例（采样是「值变了才记」，间隔天然不均）。

- **A 时间标签**：首 / 中 / 末三个点，标 `MM-DD`；若首末同日则只标 `HH:MM`（直接切 `t` 字符串，不解析日期）。
- **B 说明小字**：图底居中「按变化点等距排列，不是时间比例」——防止被误读成时间轴。
- **C 竖向淡网格**：间隔 `max(1, ceil(n/8))`，点多了也能数清第几次变化。

配套：`padB` 26 → 40（给轴标签留位），画布高度系数 260/820 → 300/820、下限 180 → 200。
