## 结论一：作息必须跟人设走

**我的原草案是错的。** 我拟了一套「上班族作息」当默认
（07:30 起床 / 09:00 上班 / 23:30 睡），并建议第一版不暴露配置。

**用户指出**：不同人设作息不同。插件 README 里的示例人设
「小夜，夜班便利店店员」，白天该睡觉、凌晨才是主场 —— 上班族作息对她完全失效。

**而且这不只是细节**：项目 README 写明驱动方式是**「人设驱动」**。
作息硬编码 = 把最像「生活」的部分从人设里摘出去了。

### 修正后机制

```
首次启动    读人设 → 问模型「按这个人设生成一天作息」→ JSON
            → 存盘 data/schedule.json

之后 tick   直接读盘（不再问模型，不烧 token）

人设改了    人设指纹变了 → 重新生成

空人设 / 生成失败 → **保守默认**（用户明确要求保守）
```

**「保守默认」的含义**：活跃时段短、动作少 —— 宁可安静，
也别顶着错的人设乱发东西。

### 顺带

「作息存盘」与早先记的「调度状态落盘」是**同一套存储机制**，一起做掉。

## 结论二：私聊与群聊分四层表现

| 层 | 私聊 | 群聊 | 归谁 |
|---|---|---|---|
| 该不该回 | 对方专门找你，就该回 | 被 @ 必回；没 @ 要掂量 | AstrBot 框架 + 插件加判断 |
| 语气 | 近、松 | 收、有分寸 | 人设 + 插件注入场景说明 |
| 长度 | 可以长 | 短，一两句 | 同上 |
| 主动性 | 基本不主动开口 | 可低概率插一句 | **插件纯新增** |

**「主动性」是唯一从零加的行为**；其余三层是在 AstrBot 已有的回复流程上「加性格」。

### 边界（沿用项目既定）

聊天与群聊是 AstrBot 框架核心能力 —— **插件只加性格与时机，不重写。**
