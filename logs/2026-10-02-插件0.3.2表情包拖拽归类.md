# 插件 0.3.2：表情包手动拖动归类（2026-10-02）

## 需求
表情包页允许把一张图**手动拖进**别的分类。此前只有「一键自动归类」（调多模态模型）与「上传到指定分类」，缺一个零成本的人工归类动作。

## 结论
已上线。表情包页每个分类区块都是拖拽落点，卡片可拖到任意分类即完成归类；拖进「其他」＝移回散图区（`default`）。**该动作只做文件移动，不调模型、零 token。**

## 设计要点
- **落点用后端下发，不在前端硬编码**。分组由 `groups_by_intent()` 产生，「其他」是 `default + collected` 的合并视图，没有单一目录名。所以 `page_stickers` 直接给每组一个 `drop` 字段：内置意图 / 用户分类 = 同名目录，「其他」= `default`。前端只认 `group.drop`，不猜。
- **同名歧义防护**。`move_by_name` 带 `from_label`（卡片当前所在目录），只在那个目录里找。`default/same.png` 与 `collected/same.png` 同名时，拖哪张就动哪张，不会误移另一张。`from` 缺失时退回全库搜索（容错）。
- **目标冲突拒绝**。目标目录已有同名文件时 `move_image` 返回「目标已存在同名文件」，不覆盖。
- **幂等提示**。落点与来源相同时返回 400「目标分类与当前相同」，前端提示「已经在这个分类里了」。

## 顺带修复：拆分脚本的一次性语义
`scripts/split_main.py` 的 docstring 原写「可重复执行」，但它的机制是**每次从 `archive/main.py-0.2.28.bak` 重新拆**。0.3.0 之后主文件已含 0.3.1 修复，一旦有人重跑该脚本，会把 0.3.1 及以后的改动全部回滚。已在该脚本加守卫：检测到 `handlers/` 存在时默认拒绝运行，确需重拆须设环境变量 `SPLIT_FORCE=1`。docstring 同步改为「一次性迁移工具，已执行完毕」。

## 冒烟清单（博士）

## 0.3.3 修正：改用指针事件（2026-10-02）

**现象**：博士真机实测「有拖拽无反应」——卡片能拖起，松手无任何回执。

**排查**：
1. 部署无问题——容器内 `app.js` 确含 `beginDrag` / `draggable`，HTML 含「手动拖动」，`docker exec grep -c` 全部命中。
2. 缓存排除——`plugin_page_service.py` 服务页面时下发 `Cache-Control: no-store`（第 432 行），浏览器不会拿到旧 `app.js`。
3. 结论：**HTML5 原生拖放的事件链没跑通**。它在触屏、以及多数 WebView / 应用内浏览器里不触发 `dragover→drop`（这类环境普遍只实现了拖起、不实现投放）。原实现只挂 `dragstart`/`dragover`/`drop`，一旦 `drop` 不触发，就表现为「无反应」。

**修法**：不再依赖 HTML5 DnD，改**指针事件自实现**（`pointerdown` → 位移超 8px 启动 → 生成跟随指针的浮层 → `pointerup` 时用 `document.elementFromPoint` 命中分类）。指针事件在鼠标 / 触屏 / WebView 都可用。

- `app.js`：删 `draggable`/`dragstart`/`drop` 与 `bindDropZone`；新增 `beginDrag`/`moveDrag`/`endDrag` 与全局 `pointermove`/`pointerup`/`pointercancel`；分组区块改用 `dataset.drop` / `dataset.label` 存落点。
- `style.css`：卡片 `touch-action:none`（触屏拖拽不滚页）、`.drag-ghost` 浮层、`body.drag-active` 抓取光标。
- 新增反馈：拖到空白处松手 → 「没有落到分类上，已取消。」

**验证**：`node --check app.js` 通过（脚本与 `.mjs` 模块两种模式）；容器内 `app.js` 含指针拖拽、`dragstart` 计数 0；双副本 `diff -rq` IDENTICAL；真机 `Plugin astrbot_plugin_tuhengyu (0.3.3)` 加载无 traceback。

**教训**：面向「浏览器 + 应用内 WebView 双环境」的交互，不要用 HTML5 DnD 作为唯一通路。`drop` 不触发是无报错的静默失败，最难排查。

## 0.3.4：空分类留落点 + 归类改为「暂存 → 保存」（2026-10-02）

**现象（博士真机两条反馈）**
1. 把某个分类下的**唯一一张**图拖走后，该分类消失，无法再拖回。
2. 每拖一张页面就闪一下，不友好；要求改成「点击保存后再提交」。

**结论**：两条均成立，分别修。

### 缺陷① 空分类消失（后端）
- **原因**：`groups_by_intent()` 原本只在 `if items:` 时输出分组。拖走最后一张图后该分组不再产生，页面落点消失，`sticker-move` 也就失去目标 —— 拖出去就回不来。
- **修法**：`core/stickers.py` 新增 `dirs()`（扫各 `root` 的一级子目录，排除 `.` 开头，跨 root 去重）；重写 `groups_by_intent()`：
  - 内置意图类目：有图，**或目录存在（哪怕为空）** → 都返回；
  - 用户自定义分类：按 `dirs()` 全量返回（含空）；
  - 兜底：索引里有图、但目录扫描未覆盖的照样返回（多根 / 异常情况）；
  - 「其他」（`default` / `collected`）：仍仅在有图时出现（无独立空目录语义）。

### 缺陷② 逐张闪（前端改为暂存 + 保存）
- **原因**：原实现每次 `drop` 都 `apiPost("sticker-move")` 后 `loadStickers(true)` 全量重载 —— 逐张请求 + 逐张重绘，造成闪屏。
- **修法**：前端引入**暂存队列 + 脏标记 + 「保存归类」按钮**。
  - 拖动只改本地：卡片 DOM 移入目标分类、更新分组计数、给卡片打 `.pending`「待保存」角标、标题栏显示「未保存 N 项」；**不发请求、不重载**。
  - `pendingMoves: Map<card, {name, from, to, label}>`，按卡片元素去重；拖回原位自动撤销该卡暂存。
  - `from` 取卡片**原始**目录（`dataset.origTag`，文件实际所在处），不是显示位置 —— 与后端 `find_path(name, from_label)` 对齐（文件此时尚未真正移动）。
  - 「其他」= `default + collected` 合并视图，比较落点时用 `normTag()` 归一（两者等同），避免「把 collected 的图拖进其他」被误判成一次真实移动。
  - 点「保存归类」→ 逐条 `POST /sticker-move` → 清空暂存 → **只** `loadStickers(true)` 一次 → 回执「保存完成：成功 N 项（失败 M 项）」。
  - 重载会重建 DOM：`loadStickers(true)` 前若仍有未保存项会 `confirm` 提示；重载后清空暂存。
  - 空分类落点：网格无卡片时放一个 `.gallery-empty` 占位块（「拖图到这里」），既提示又能接拖拽。

### 冒烟清单（博士）
1. 打开「表情包」页签，把一个分类里唯一一张图拖到别的分类 → 原分类**仍在**（显示「0 张」+「拖图到这里」占位），卡片带橙色「待保存」角标。
2. 顶部出现「未保存 N 项」，「保存归类」按钮变为可点。
3. 点「保存归类」→ 只刷新一次 → 回执「保存完成：成功 N 项」。
4. 反向：把图拖回刚清空的分类 → 能落进去（该分类落点还在）。
5. 拖动过程**不再逐张闪**；有未保存项时点「刷新」会先弹确认。

### 教训
1. **空分类必须留得住落点** —— 目录存在即为分组；否则用户拖出去就回不来。
2. **批量提交优于逐张提交** —— 减少请求与重绘，也顺带消除了闪屏。
