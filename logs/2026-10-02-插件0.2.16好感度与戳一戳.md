## 三、技术核实（VPS AstrBot v4.28.2，源码级）

### 3.1 戳一戳能不能收 —— 能

- `platform/sources/aiocqhttp/aiocqhttp_platform_adapter.py:75` `@self.bot.on_notice()` → `convert_message` → `handle_msg`，**notice 事件进正常消息管道**。
- 同文件 `:168` `_convert_handle_notice_event()`：`sub_type=="poke" and "target_id" in event` 时 `abm.message.append(Poke(id=str(event["target_id"])))`。
- `abm.type` 按有无 `group_id` 判为 GROUP_MESSAGE / FRIEND_MESSAGE。
- 因此**可以走普通 handler**，但 registry 层没有 notice 专用 filter（`api/event/filter/` 只有 `event_message_type / command / regex / permission / platform_adapter_type / custom_filter / llm_tool / after_message_sent`），只能用 `EventMessageType.ALL`，再在函数里判组件。

### 3.2 关键风险点：会不会误触默认 LLM —— 分群聊/私聊

`pipeline/waking_check/stage.py`：
- handler filter 通过只置 `is_wake=True`，**不置** `is_at_or_wake_command`；
- `is_at_or_wake_command` 只在 wake_prefix 命中、或消息里有 At(bot)/AtAll/Reply(bot) 时置 True；
- **私聊分支无条件置 `is_at_or_wake_command=True`**。

`pipeline/process_stage/stage.py:55-59`：默认 LLM 调用条件为
`not event._has_send_oper and event.is_at_or_wake_command and not event.call_llm`。

结论：
- **群聊被戳**（未 @）→ `is_at_or_wake_command` 仍为 False → 不会误触 LLM，安全。
- **私聊被戳** → 该标志为 True → **会触发默认 LLM**（且 `message_str` 为空）→ 插件内必须 `event.should_call_llm(True)` 掐掉。

`astr_message_event.py:372-377` `should_call_llm(bool)` 的 docstring 是「是否在此消息事件中**禁止**默认的 LLM 请求」，与字段名 `call_llm` 语义相反，用的时候不要被名字骗到。

### 3.3 戳一戳能不能发 —— 能，但平台兼容性留了后手

- `core/message/components.py:614` `class Poke`，`_type` 默认 `"126"`，`target_id()` 兼容 `id`/`qq`，`toDict()` 输出 `{"type":"poke","data":{...}}`。
- `platform/sources/aiocqhttp/aiocqhttp_message_event.py:67` 兜底分支：`return segment.toDict()`，即 Poke 会作为 `poke` 段随 `send_group_msg` / `send_private_msg` 发出。
- **未验证**：SnowLuma（OneBot 端）是否接受 `poke` 段。故回戳**单独发送并 try/except**，失败只记 warning，不拖累文字。

## 四、落地设计

### 4.1 好感度（`core/favour.py`，自研）

- 三维：`favour`（整数，-100~100）/ `attitude`（印象）/ `relationship`（关系），默认 `0 / 中立 / 陌生人`。
- 存储：插件数据目录 `favour.json`；键 = 用户 QQ，`session_based` 开启时前缀 `unified_msg_origin`。
- 写入：`FavourStore.update()` 夹逼 -100~100；**只覆盖传入字段**，缺字段保持原值。
- 回写格式：**单行** `%%FAV%% <好感> | <印象> | <关系>`。
  - `_MARKER_FIND` 用 `finditer` 收全部；
  - `_MARKER_STRIP` 用 `sub` 整行（含行尾换行）剥离；
  - 坏数字只跳过该字段，不整体丢弃。
  - **没有方括号结构 → 碎块残留不可能发生**，从格式上根除第三方那个 bug。
- 注入：`build_injection(state)` 追加到 `req.system_prompt`，含当前三维 + 好感区间语气要求 + 更新指令。
- 好感区间（决定语气）：`75+ 亲密信赖 / 40+ 友好 / -10+ 中立礼貌 / -50+ 反感 / 以下 厌恶敌对`。

### 4.2 戳一戳（`core/poke.py`）

决策顺序（纯函数 `decide()`，可单测）：

| 条件 | 反应 | kind |
|---|---|---|
| 冷却中（同人同会话，默认 30s） | 不理 | ignore |
| 同一人窗口内（默认 60s）连戳达阈值（默认 3，含本次） | 怼一句 | snap |
| 作息 `awake=false` | 不理 | ignore |
| 好感 ≥ 40 | 75% 回戳+说话 / 25% 只回戳 | both / silent_poke |
| 好感 < -10 | 60% 不理 / 40% 冷一句 | ignore / text |
| 普通 | 60% 只回戳 / 40% 问一句 | silent_poke / text |

- 文字走模型（`build_poke_prompt`，群聊 ≤20 字 / 私聊 ≤30 字；SNAP 时要求「烦了、怼一句、不带脏字」）；拿不到模型或人设为空 → `fallback_text()` 回落内置短句池。
- 回戳：`event.send(MessageChain([Poke(id=uid)]))`，单独发、try/except。
- 私聊：无论回不回，进 poke 分支就先 `event.should_call_llm(True)`。

### 4.3 新增 handler（`main.py`）

| handler | 装饰器 | 作用 |
|---|---|---|
| `inject_favour` | `@filter.on_llm_request()` | 追加状态说明 + 更新指令 |
| `collect_favour` | `@filter.on_llm_response()` | 剥离状态行 + 落库 |
| `on_poke` | `@filter.event_message_type(EventMessageType.ALL)` | 判 Poke 组件 → 决策 → 发戳 / 发文字 |
| `favour_status` | `@filter.command("图恒宇好感")` | 只读查看自己的三维状态 |

配置新增两段（`_conf_schema.json`）：`favour`（enabled / inject / session_based）、`poke`（enabled / use_model / cooldown_seconds / repeat_window_seconds / snap_threshold / poke_back_prob / model）。

## 六、已知边界

1. `EventMessageType.ALL` 意味着 `on_poke` 会**对每条消息**被调用一次，内部靠 `isinstance(m, Poke)` 秒退。这是 registry 无 notice 专用 filter 的必然代价。
2. 副作用：filter 通过会置 `is_wake=True`（非 `is_at_or_wake_command`），因此群聊不会因此多说话；但 `_umo_auto_name_recorder` 会照常记录会话名（上游行为，无害）。
3. 回戳依赖 OneBot `poke` 段，平台不吃时只有 warning，表现为「不回戳、只说话或不说话」。
4. 好感度依赖模型照格式回写。模型不写 → 状态不变（不会错乱）。写坏 → 该字段跳过。
5. 注入的是 system prompt，对**该会话所有 LLM 请求**生效（与第三方同构）。

## 0.3.7：好感度长期不变修复（2026-10-02）

**真机反馈**：`/图恒宇好感` 反复看都是 0，与人聊了多轮也不动。

**排查（零侵入，读会话库）**：直接查 `data_v4.db` 的 `conversations.content`：
- rowid=1 的思考链原文：`No need for the FAV line since there's no relationship change needed - this is just a casual greeting` —— 模型**主动决定省略**状态行。
- rowid=2 的正文结尾确有 `%%FAV%% 1 | 友善 | 陌生人`，且 `favour.json` 的 `2681711819 → favour:1 / attitude:友善 / relationship:陌生人` 与之一致 —— **写入链路是通的**。
- `token_stats.json` 由 `collect_favour` 开头调 `_tok_output`，它今日有数据（`reqs:14`）→ 证明 `on_llm_response` 钩子确实在跑。

**根因**：`build_injection` 的指令写了「本轮无需改动就整行省略」。推理模型（LongCat-2.5-Preview）倾向照字面执行 —— 多数轮次判「无需改动」就整行省略，于是不落盘，看起来永远不动。

**修法（`core/favour.py` `build_injection`）**：删「本轮无需改动就整行省略」，改为「每一轮回复都必须在最后另起一行输出状态行；即使本轮没有任何变化，也要照写当前值，不得省略这一行」。其余规则（绝对值、+1~+3 / -3~-10、印象关系与好感一致）不变。

**验证**：双副本 IDENTICAL（`core/favour.py` md5 `a1820f7b…`）；`docker restart` 后日志 `Plugin astrbot_plugin_tuhengyu (0.3.7)` + 调度器已启动，无 traceback。**待博士再聊几轮复验数值是否开始变。**

**边界更新**：原「已知边界 4」由「模型不写就状态不变」收窄 —— 现在插件已强制每轮必写，除非模型连强制指令也不遵守。
