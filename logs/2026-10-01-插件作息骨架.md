# 工作日志 · 2026-10-01 · 插件作息骨架

## 背景

插件第二阶段的第 2、3 条：把「活跃时段」换成**作息表**。

原实现只有 `in_active_hours()` —— 一串 `09:00-23:00`，只能回答「醒着吗」。
结果：凌晨和中午发的东西没有区别，**崩人设**。

## 做了什么

作息**跟人设走**：首次启动读人设 → 问模型生成一份一天作息 → 存盘。
之后直接读盘（不烧 token）。人设按指纹变了才重算。

## 关键前提（本轮查证）

**1. `_conf_schema.json` 的 object 是嵌套 dict**

`astrbot/core/config/astrbot_config.py:145`：

```python
def _config_schema_to_default_config(self, schema: dict) -> dict:
    def _parse_schema(schema: dict, conf: dict) -> None:
        for k, v in schema.items():
            ...
            if v["type"] == "object":
                _parse_schema(v["items"], conf[k])
```

→ 读法是 `config["schedule"]["manual_hours"]`，**不是**扁平 key。
→ 旧代码全用扁平 key，不改就全部读空。**这是本轮最大的坑。**

**2. schema 同时提供默认值**

`AstrBotConfig(config_path=..., schema=...)` —— schema 决定默认值，
所以**改 schema 不会丢旧值**，但字段名变了的位置需要重填。

**3. 数据目录**

```python
from astrbot.core.utils.astrbot_path import get_astrbot_plugin_data_path
# → data/plugin_data
# 另有 StarTools.get_data_dir(plugin_name) 会自动建目录
```

`main.py` 里做了 try/except 兜底：API 变动时退回插件目录旁。

## 设计

```
人设 → sha256 前 16 位指纹
  ↓ 首次 / 人设变了
问模型生成 JSON → 存 data/plugin_data/astrbot_plugin_tuhengyu/schedule.json
  ↓ 之后每次 tick
读内存 → state_at(now) → {awake, scene, state, source}
  ↓ awake?
掷骰子 → 行动
```

**兜底链**（三层，全部退到保守默认 09:00–23:00 醒）：

1. 人设空 → 保守
2. 生成失败 → 保守
3. 时间没命中任何时段 → 保守（睡着）

理由：**宁可安静，也别顶着错的人设乱发东西。**

**容错**：模型可能输出 ```json 包裹或带前后废话 → 单独 `extract_json()` 抠 JSON。
