## 本轮改动

### A 类：健壮性（已改）

**A1 设置保存静默成功**（`main.py: page_settings_post`）
旧：`if callable(save): save()`，无 `save_config` 时接口仍返回 `ok:true`，用户以为存了。
新：保存失败抛 500；缺 `save_config` 时响应带 `saved:false` + `status.message` 提示「改到内存但没落盘，去官方页保存」。

**A2 空值被写成 0**（`main.py: _coerce`）
旧：`int("")` / `float("")` 抛异常 → 返回 `0` / `0.0`。用户在设置页清空一个数值框，保存后该字段变 0。
新：`blank`（None / 空白串）时回落 schema 默认值；bool 空值回落默认布尔。

**A4 「判不出」与「调用失败」混为一谈**（`core/classify.py` + `main.py: page_sticker_classify`）
旧：`classify_image` 失败也返回 `FALLBACK`（「其他」），统计里只体现为「留在其他」。
新：`classify_image` 返回 `str | None`——`None` = 调用失败。归类接口据此把 `failed += 1` 单独计数。

**A5 收集表情包可能收到 bot 自己的图**（`main.py: collect_sticker`）
加守卫：`sender == self_id` 直接返回（与 0.2.27 戳一戳同一类回环防护）。

**A6 识图归类写死默认模型**（`main.py` + `_conf_schema.json`）
新增配置 `sticker.classify_model`（`select_provider`）。归类优先用它，没配才回落 AstrBot 默认模型。
理由：默认对话模型若不支持多模态，归类会 100% 失败，此前无法指定。

### B 类：冗余（已改）

- **B1** 表情包两条发送路径（`attach_sticker` / `send_sticker_separately`）前 26 行逐行重复 → 抽 `_sticker_reply_b64(event)`，两条路径只保留「发」的一段。顺带保证概率只掷一次。
- **B3** 配置分组取值三行模式重复六处 → 抽 `_sec(name)`，`_favour_cfg` / `_poke_cfg` / `_proactive_cfg` 及三个 handler 全部改调用。
- **B4** 数据文件路径拼接 → 抽 `_data_file(name)`，`_proactive_path` / `_tok_path` 改调用。
- **B2** `import os` / `import json` 上提模块顶层，删除 7 处函数内重复（`_load_schema` / `_config_values` / `_merge_settings` / `_proactive_load` / `_proactive_save` / `_tok_load` / `_tok_save`）。
  残留的局部 import 均为合理延迟加载（`astrbot.*` 内部路径、`re` / `base64` / `time as _time`）。
