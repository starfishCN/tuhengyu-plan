# 工作日志 · 2026-10-01 · 插件自定义页面（运行状态）

## 目标

在 AstrBot WebUI 内给插件加一页自定义页面，替代「敲 `/图恒宇` 看文本回执」。
产出：运行状态面板（此刻作息 / 触发概率 / 时段表）+「重算作息」按钮。

## 一、调研：AstrBot 插件页面机制（源码 + 官方文档双向核对）

官方文档：`https://docs.astrbot.app/dev/star/guides/plugin-pages.html`（本轮首次找到并采信）。

| 项 | 结论 | 依据 |
|---|---|---|
| 页面落点 | `pages/<page_name>/index.html`，**自动发现**（目录扫描），无 index.html 的目录忽略 | 官方文档 + `plugin_page_service.discover_plugin_pages` |
| page_name 限制 | 非空、无 `/`、无 `\`、非 `.`/`..`、不以 `.` 开头 | 官方文档 + `normalize_plugin_page_name` |
| 页面标题 | i18n `.astrbot-plugin/i18n/<locale>.json` 的 `pages.<page_name>.title`；缺省回落到 page_name | `plugin_page_service` + 官方文档 |
| 内嵌方式 | 受限 iframe，经 `plugin_page_bridge.js` 通信 | 官方文档 |
| 前端调用 | `bridge.apiGet(endpoint, params)` / `apiPost(endpoint, body)`；endpoint 为**插件内相对路径**（不含插件名） | 官方文档 |
| **路由前缀** | **注册路由必须带插件名前缀** `/astrbot_plugin_tuhengyu/<endpoint>` | 官方文档明确写「路由需要包含插件名作为前缀」 |
| 实际匹配 | URL `/api/v1/plugins/extensions/<plugin.name>/<endpoint>` → `plugin_path` 参数 → `request_path = "/"+plugin_path` → 与注册路由正则全匹配 | `plugins.py:166 _match_registered_web_api`、JSON 的 `pluginName: plugin.name` |
| handler 入参 | 路由里的 `<name>` 占位作为**关键字参数**传入；请求对象走 `from astrbot.api.web import request` 上下文代理 | `plugins.py:217 view_handler(**path_values)` + 官方文档 |
| 响应 helper | `json_response` / `error_response` / `file_response` / `stream_response` | 官方文档 |
| bridge SDK | 服务端返回 HTML 时**自动注入** `/api/plugin/page/bridge-sdk.js`，无需手动引入 | 实测页面 HTML 中出现该 script 标签 |

关键坑：`_match_registered_web_api` 收到的是**去掉 `/api/v1/plugins/extensions/` 之后的完整路径**（含插件名），
而 `register_web_api` 不会自动补前缀 —— 所以插件自己注册时必须写全 `/astrbot_plugin_tuhengyu/status`。

另有次要发现：`plugin_page_service` 下发页面内容时会把 HTML 里的**相对路径改写为绝对路径并附 `asset_token`**
（实测 `<link href="./style.css">` → `/api/plugin/page/content/<plugin>/status/style.css?asset_token=…`），
因此页面用相对引用即可，不必手写 token。

## 五、取令牌的方式修正（重要）

0.2.3 那轮记的「密码长度 32」是**看错了字段**。实测：

- AstrBot 4.x 的登录口令是 `dashboard.pbkdf2_password`（`pbkdf2_sha256$600000$<salt32>$<hash64>`，共 **118** 字符）；
- `dashboard.password` 是**遗留 md5 字段**，登录时被忽略；
- 判定逻辑在 `astrbot/dashboard/password_state.py`：有可用的 `pbkdf2_password` 时 `is_password_storage_upgraded` 为真，`get_dashboard_password_hash` 只返回它。

所以上一轮「写 `dashboard.password` 没用」不是配置没生效，是写错了字段。本轮改写成 `pbkdf2_password` 后，登录一次通过。验证完同样还原配置并重启，复测 401，原密码原样保留。

临时脚本 `scripts/verify_setpw.py`（set/restore 两态）与 `scripts/verify_probe_routes.py`（patch/restore）已留档在本地仓库，方便下次验证复用。
