# 工作日志 · 2026-10-01 · 面板「读取初始凭据」功能

## 起因

用户提出：**教程面向小白，但 AstrBot / SnowLuma / noVNC 的初始密码小白找不到。**
建议给面板加个功能把密码抓出来。

判断：**该加，且这是教程最后一块没堵上的短板。**

## 一、先实测：密码到底在哪

在验证机（183.66.27.21）上逐项确认，结果**推翻了教程里的两处写法**：

| 密码 | 实际来源 | 特性 |
|---|---|---|
| **noVNC 远程桌面** | **容器环境变量** `VNC_PASSWD`（`docker inspect` 可读） | ✅ 稳定 |
| **AstrBot 控制台** | 启动日志 `➜  Initial password: xxx` | ⚠️ 仅首次启动 |
| **SnowLuma 控制台** | 启动日志 `initial credentials: user=admin password=xxx` | ⚠️ 仅首次；未改密时重启会换 |

### 教程写错的两处（本轮已修）

**错误一（04 篇）**：原写「远程桌面密码从 `docker logs` 里 grep」。

**实际**：日志里只有 `stored passwd in file: /root/.vnc/passwd`（**只有路径，没有明文**）。
明文在容器环境变量里，由 `/root/snowluma/.env` 的 `VNC_PASSWD` 注入。

**错误二（04 篇）**：原写「密码只打印一次，错过就查不到了」。

**实际**：SnowLuma 日志里有一句
`previous bootstrap password was never rotated; regenerated a new one`
—— **未改密时，重启会重新生成一个新密码**。所以「抓一次存下来」对 SnowLuma 不成立，
必须**登录后立刻改密**。

## 二、实现

| 文件 | 改动 |
|---|---|
| `panel/core/credentials.py` | **新增**。三段探测命令 + `gather()` |
| `panel/core/runner.py` | **新增** `run_capture()` —— 取回输出，不刷日志（密码不该进日志流） |
| `panel/main.py` | **新增** `credential_section()` + 一个折叠区「找不到密码？点这里读初始凭据」 |

### 设计取舍

- **不把密码推进日志窗口**：日志是公开可见的滚动区，密码进日志等于二次暴露。
  故新写 `run_capture`，绕过 `run_stream` 的逐行回调。
- **明确标注「初始密码」**：页面顶部有醒目提示「如果你已经改过密码，这里显示的是旧值」。
  不能让小白误以为这是当前密码，否则改完密登录不上会更慌。
- **同时列出端口表**：顺带把 6081 / 5099 / 6185 / 6199 的用途写清楚，
  并标注 6199「绝对不要映射到公网」。
- **复制按钮**：密码是随机串，手抄易错，给了一键复制。

## 三、踩到的两个坑（值得记）

**坑一：`tail -1` 在本机报 `option used in invalid context`**

同一台机器上，`docker inspect ... | tail -1` 正常，但
`docker logs ... | grep ... | tail -2` 直接报错。

**处置**：全部改成 POSIX 规范写法 `tail -n 1`。**这个坑会导致整段管道静默失败**，
表现为「读不到密码」，极难查。

**坑二：`sed 's/.*Initial password[: ]*//'` 有歧义**

`[: ]` 在 `[...]` 里会被某些 sed 实现当作 POSIX 字符类（`[:alpha:]` 那种）的开头。

**处置**：改成明确的 `s/.*Initial password: *//`。

## 四、部署过程中发现的问题

**问题：VPS 上的面板仓库停在上古版本 `7f07ea8`，且无法 `git pull`。**

两个原因：

1. **remote 指向 GitHub** —— 而这台机器**无国际出口**，`git pull` 超时 **130 秒**。
   （`install.sh` 的逻辑是先 Gitee 后 GitHub，但 VPS 上这份 remote 是 GitHub。）
2. **有本地未提交改动 + 未跟踪文件**（`core/sources.py`、`main.py`、`vendor/snowluma_install.sh`），
   `pull` 被 abort。

**处置**：放弃 `git pull`，改**直接 scp 覆盖三个文件**后 `systemctl restart`。

**副作用记录**：过程中误杀了一个面板进程（`kill -9 43989`），
systemd 因 `Restart=always` 自动拉起，无实际影响。

**另一个虚惊**：发现有第二个 `python main.py` 进程反复出现、杀不掉。
追查其父进程发现是 `containerd-shim-runc-v2` —— **它是 Docker 容器内的进程，与面板无关。**

> ⚠️ **给后续接续者的提醒**：VPS 上 `/opt/tuhengyu-panel` 的 git remote 仍是 GitHub，
> 在无国际出口的机器上 `git pull` 会卡 130 秒。
> 要么改 remote 为 Gitee，要么直接 scp 覆盖文件。
