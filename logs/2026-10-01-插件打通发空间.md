# 工作日志 · 2026-10-01 · 插件打通发空间（项目核心目标达成）

## 本轮目标

开发配套插件第一版（作息 + 调度器 + 发空间），解决长期卡点：**OneBot 没有「发空间」动作**。

## 结论

**打通了。插件已在真实环境发出第一条说说。**

```
QQ 消息 → SnowLuma → AstrBot → 插件 → LongCat 生成内容
       → OneBot 取 cookie → bkn 算 g_tk → POST 空间接口
       → QQ 空间出现动态 → 回信
```

---

## 一、卡点的解决过程

### 1. 先确认协议端到底有没有这个能力

直接对 SnowLuma 的 OneBot 接口做了一轮探测（`scripts/probe_snowluma_api.py`）：

| 动作 | 结果 |
|---|---|
| `get_version_info` | ok，`SnowLuma 1.14.20-node`，`protocol_version v11` |
| **`get_cookies`** | **ok，返回含 p_skey/skey/uin 的 cookie** |
| **`get_csrf_token`** | **ok，返回 token（但空间接口用不上）** |
| `set_qq_profile` | ok |
| `send_group_notice` / `get_user_state` / `get_qq_avatar` | `unknown action` |
| **发空间相关动作** | **不存在** |

→ 结论：**协议端不提供发空间**，必须直连空间 Web 接口。

### 2. 关键启发来自旧插件的源码

本地有 `astrbot_plugin_qzone_ultra` 的完整源码（`PRTS/plugin_src/`）。从中读到三条决定性信息：

1. **必须带 `domain` 参数去要 cookie**（`onebot_cookie.py` 的 `iter_cookie_domains`）。
2. **g_tk 由 `p_skey` 算**，不是 `get_csrf_token`（`parser.py` 的 `COOKIE_SECRET_KEYS`：p_skey → skey → pskey → skey2）。
3. 发布接口的完整字段（`client.py: publish_mood`）。

### 3. 实测踩的坑

| 尝试 | 结果 | 原因 |
|---|---|---|
| 不带 domain 取 cookie + 自己的 g_tk | `请先登录空间`（-3000） | cookie 不在空间域，p_skey 不适用 |
| 带 domain，但用 `get_csrf_token` 当 g_tk | 同样 -3000 | g_tk 必须由 p_skey 算 |
| 用 `https://user.qzone.qq.com` 当 domain | 返回 0 字节 | domain 只填主机名 |
| **带 domain + p_skey 算 g_tk** | **code:0 ✅** | 正确姿势 |

各域实测（`scripts/test_qzone_read3.py`）：

| domain | cookie 长度 | p_skey | 结果 |
|---|---|---|---|
| `user.qzone.qq.com` | 476 | ✅ | **鉴权通过** |
| `qzone.qq.com` | 441 | ✅ | — |
| `h5.qzone.qq.com` | 488 | ✅ | — |
| `https://user.qzone.qq.com` | 0 | ❌ | 格式错 |

## 二、插件实现

### 文件结构

```
plugin/astrbot_plugin_tuhengyu/
├── main.py                 插件入口（Star 子类、生命周期、两条命令）
├── metadata.yaml           元信息（v0.2.0）
├── _conf_schema.json       配置项
├── core/
│   ├── onebot.py           OneBotBridge：取空间 cookie
│   ├── qzone.py            QzoneClient：bkn / 发布 / 读取
│   ├── llm.py              内容生成（走 AstrBot 的模型）
│   └── scheduler.py        作息 + 调度器 + 行动
├── assets/stickers/        （预留）
└── pages/                  （预留）
```

### AstrBot v4 API 核对（从容器源码读出，非猜测）

| 项 | 结论 |
|---|---|
| `Star.__init__` | `(self, context: Context, config: dict \| None = None)` |
| `@register` 装饰器 | **已废弃**（v3.5.19 后不需要），元信息走 `metadata.yaml` |
| 生命周期 | 实例方法 `async def initialize(self)` / `async def terminate(self)` |
| 取平台 | `context.get_platform("aiocqhttp")` → `platform.get_client()` → `CQHttp` |
| 调动作 | `await bot.call_action(action, **params)` |
| 生成内容 | `await context.llm_generate(chat_provider_id=..., prompt=..., system_prompt=...)` |
| 日志 | `self.logger`（插件独立 logger） |

### 关键代码要点

```python
# core/qzone.py —— bkn
def bkn(skey: str) -> int:
    h = 5381
    for ch in skey:
        h += (h << 5) + ord(ch)
    return h & 0x7FFFFFFF
```

```python
# core/onebot.py —— 必须带 domain
resp = await self.call("get_cookies", domain="user.qzone.qq.com")
```

发布字段（14 个，取自 qzone_ultra 的生产实现）：
`syn_tweet_verson / paramstr / who / con / feedversion / ver / ugc_right /
to_sign / hostuin / code_version / richval / issyncweibo / format / qzreferrer`

## 三、部署与实测

scp tuhengyu_plugin.tgz root@vps:/root/

## 五、风险与限制

- **空间接口是逆向的**，官方随时可能改动；`code` 非 0 时插件只记日志不重试。
- **触发频率需克制**：主动行为是非官方 bot 的封号高危区。当前默认「最短间隔 6 小时 + 每次检查 15% 概率」。
- 登录态失效（`code:-3000`）时插件会清掉缓存 cookie，下次重新取。
