# 插件 0.2.18 —— 戳一戳实戳后暴露的两处修复

日期：2026-10-02
版本：0.2.17 → 0.2.18
提交：`1c17e0f`（Gitee `7d8f31c..1c17e0f`；GitHub 同区间，本机 `/root/_gitee_clone` 推）

## 起因（博士实戳反馈）

「光第一下说了一句在呢，没看出附带人格，剩下后面都在回戳。」

## 症状与真机日志对照（已验证）

真机日志（08:22–08:25 共 9 次 Poke 事件）给出两条线索：

1. `[图恒宇] 回戳失败：协议端未接受 send_poke 动作。` —— 只出现 2 次（应为回戳的分支）。
2. 08:22:41 前后**没有任何 LLM 请求日志** —— 说明模型根本没被调用。

## 根因一：成功判据把成功判成失败

`send_poke` 的 `run` 返回 `okResponse()`，序列化为 `{"status":"ok","retcode":0,"data":null}`。
aiocqhttp 的 `call_action` 返回 `result["data"]`，即 **None**。
我们的 `_send_poke` 用 `resp is not None` 判成败 → 明明发成功了却记 warning，还返回 False。

**验证**：在宿主上直接对 SnowLuma HTTP 口（`:3000`，token `4oSJFxpVq0hjca8JpLXFstzcBUSU-XW-JBENqeIX5d4`）调
`send_poke {user_id:2664648140}` → `{"status":"ok","retcode":0,"data":null}`。
`friend_poke`、字符串型 user_id 同。动作名、参数均正确。

→ **博士看到的「后面都在回戳」是真的，poke 一直在发；只是我们把它记成了失败。**

修复：`core/onebot.py` 新增 `call_ok(action, **params) -> bool`，只要 `call_action` 不抛异常即算成功；
`_send_poke` 改用它。

## 根因二：模型路径从未被调用

`_poke_text` 里取模型用的是：
```python
pid = str(psec.get("model", "") or "").strip()
if not pid:
    pid = await resolve_provider_id(self.context, "")
if not pid:
    return ""          # ← 静默返回，无日志
```
`resolve_provider_id(ctx, "")` 内部是 `getattr(prov, "provider_config", {}).get("id") or getattr(prov, "id", "")`，
对默认 provider 取不到 id → 返回 "" → 直接 return → **回落台词池**。「在呢」正是 `text_normal` 池里的一句。

同时「发空间」不受影响，因为它走 `moment.provider_id` 配置（博士填过），没走这条空 id 路径。

修复：新增 `_pick_provider(sec)`——优先 `context.get_provider_by_id(配置 id)`，否则 `context.get_using_provider()`，
拿到 provider 对象后直接 `await provider.text_chat(prompt=..., system_prompt=persona)`
（与 `core/classify.py` 同一套路）。两处静默 return 各补一条 INFO 日志，便于下次定位。

## 行为调整（回应「后面都在回戳」）

`core/poke.py` 的 `decide()`：普通关系原为
`SILENT_POKE（只回戳）if rand < poke_back_prob else TEXT`，0.6 概率纯回戳不说话。
改为 **必答一句**：`poke_back_prob` 概率 `BOTH`（回戳 + 说话），否则 `TEXT`。
好感高、好感低、冷却、连戳分支不变。

## 方法教训

- **协议端动作不能拿返回值判成败**：OneBot 动作成功常返回 `data:null`，正确判据是「没抛异常」。
- **静默 return 是排查黑洞**：两处 `return ""` 都没日志，导致「为什么没人格」无从查起。凡「有兜底但静默」的分支都应留痕。
- **直接打协议端 HTTP 口是最快的证伪手段**：一次 curl 就排除了「动作不存在」这一大类假设。
