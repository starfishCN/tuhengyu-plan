# 工作日志 · 2026-10-01 · 面板安全默认（无密码兜底）

## 起因

用户问「我这边 webui 改变，我仓库里的部署之后也是这个样吧」。

**界面**的答案是一样。但顺着这个问题核对部署链路时，
**发现了一处不一致，而且是安全洞**。

## 发现的问题

面板的登录认证靠两个环境变量传入：

```python
if not PANEL_PASS:
    return await call_next(request)   # ← 没设密码 = 完全不拦
```

而这三处的状态是错位的：

| 位置 | 状态 |
|---|---|
| 仓库 `deploy/tuhengyu-panel.service` | ✅ 带 `Environment=PANEL_USER/PANEL_PASS` |
| **教程 02 篇让读者手写的 service** | ❌ **只有 `ExecStart`，漏了这两行** |
| `install.sh` | ❌ **根本不装 service** |

**后果**：完全照教程做的使用者，`PANEL_PASS` 为空 → **面板连登录框都不弹**。
而这个面板**能执行任意系统命令**（装 Docker、写 daemon.json、重启容器），
公网暴露等于把机器的 root 权限挂在网上。

**这是教程的洞，也是设计上的脆弱点** —— 认证依赖外部配置，
而配置漏了没有任何提示。

## 三层修复

### A. 教程 02 篇（堵洞）

- 改为**直接用仓库里现成的 service 文件**：
  `cp /opt/tuhengyu-panel/deploy/tuhengyu-panel.service /etc/systemd/system/`
- 加醒目警告：**不要手写**，并说明漏了 `Environment` 会怎样
- 附「如果确实要手写」的最小正确片段

### B. `install.sh` 自动装服务（少一步）

```bash
SERVICE=/etc/systemd/system/tuhengyu-panel.service
if [ -f "${SERVICE}" ]; then
  systemctl restart tuhengyu-panel
else
  cp "${INSTALL_DIR}/deploy/tuhengyu-panel.service" "${SERVICE}"
  systemctl daemon-reload
  systemctl enable --now tuhengyu-panel
fi
```

幂等：已存在则只重启，不覆盖用户改过的配置。

### C. 代码兜底（**最关键**）

`main.py` 改为**三级回退**，保证「绝不会无密码运行」：

| 顺序 | 来源 | 特性 |
|---|---|---|
| 1 | 环境变量 `PANEL_PASS` | systemd / 手动设的，优先 |
| 2 | 安装目录下的 `.panel_pass` | **首次自动生成并保存**，重启后不变 |
| 3 | 内存随机值 | 目录只读时的兜底，明确警告会变 |

并在启动时**打印**：

```
================================================================
[图恒宇] 未通过环境变量设置面板密码。
[图恒宇] 已自动生成并写入：/opt/tuhengyu-panel/.panel_pass
[图恒宇]   用户名: admin
[图恒宇]   密  码: vJrluz0WZ85ZV9hL
================================================================
```

**设计取舍**：为什么存文件而不是每次随机生成？
因为「每次重启换密码」会让人每次都得翻日志，体验差到没人愿意用。
存文件（权限 600）换来「配一次、一直可用」，才有实际约束力。

## 配套防护

`.gitignore` 补上两条 —— **这两样绝不能入库**：

```
.panel_pass     # 自动生成的面板密码
data/           # 面板运行时数据（容器挂载点）
```

已确认：推送后 `git ls-files | grep -c panel_pass` = **0**。

## 教训

**「认证依赖外部配置」是脆弱设计。** 只要配置可能被漏掉，
就必须在代码里做兜底 —— 因为漏掉时**不会有任何报错**，
表现为「哦，不弹登录框，那就算了」，而使用者根本不知道这是异常。

**改法**：让「安全的默认值」成为**默认行为**，配置只用来**覆盖**它。
