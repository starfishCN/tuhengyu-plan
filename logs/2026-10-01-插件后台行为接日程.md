## 设计要点

**1. 掷骰从 `tick` 搬进 `act`**

原来 `tick()` 先掷一次骰再调 `act()`。这样将来每加一种行动，
都会共用同一次掷骰结果，没法给不同行动各自的适用条件与冷却。
现在 `act()` 内部自己判门槛、自己掷。

**2. 状态加权是关键词模糊匹配**

作息里的 scene / state 是模型自由文本，没法结构化，只能匹配关键词：

```
忙 / 工作 / 上班 / 上课 / 学习 / 考试 / 开会 / 加班 / 赶 / 通勤 / 车里   → 0.35
闲 / 空 / 休息 / 放松 / 发呆 / 散步 / 咖啡 / 茶 / 听歌 / 躺 / 阳台 / 夜 → 1.60
都不命中                                                              → 1.00
```

- 低权重组优先（先匹配先返回）：「上班摸鱼」判为忙。
- 结果概率 `= 基础概率 × 倍数`，**封顶 0.90**（`PROB_CAP`），下限 0。
- 可用 `scheduler.state_bias` 一键关掉。

**3. 生成内容拼「此刻」**

```
原 prompt + "\n\n此刻你正在上班（心情：疲惫），内容要跟这个时刻对得上。"
```

`state_line` 为空（拿不到状态）时原样返回 —— 保持旧行为，不打折。

**4. `/图恒宇` 状态行跟着改**

```
触发概率：0.15 × 状态 0.35 → 0.05
```

关掉加权时显示「触发概率：0.15（状态加权已关）」。
