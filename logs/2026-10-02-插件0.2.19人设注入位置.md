1. 真机日志显示 08:36:32 发出「在呢，有什么事吗？」——**不是回落台词池里的句子**，说明模型确实被调用了。
2. 读 AstrBot 源码确认：
   - `should_call_llm(True)` 实为**抑制**默认 LLM（判据 `not event.call_llm`），原写法正确，默认管道没掺和。
   - `Context.llm_generate` 只是转调 `prov.text_chat(...)`，与 `provider.text_chat` 同路，参数一致。
3. 查人格库（`data_v4.db` 的 `personas` 表）：默认人格 `persona_id="测试"`，`system_prompt` 6375 字，正文确为月見ヤチヨ卡 → persona 非空、内容正确。

也就是说：**人格拿到了、模型调了、提示也带了，但模型没照人设答。**

## 对照实验（决定性）

取出真机 provider 配置（`openai/LongCat-2.5-Preview`，`https://api.longcat.chat/openai/v1`）与同一份 6375 字人格，直接打 `/chat/completions`：

| 组 | 做法 | 结果 |
|---|---|---|
| 空 system | 只给任务 | 「你好呀，有什么事吗？」 |
| A | 人设放 **system** | 「在呢，有什么事吗？」← 复现线上症状 |
| B | 人设拼进 **user** | 「哦呀，戳我干嘛呀」 |
| C / D | 短人设 system / 短人设 | 均在角色内 |

再采样定量（每组 6 次）：

| 组 | 配置 | 输出 |
|---|---|---|
| A | system 人设 + 原 task，t0.8 | 2/6 客服腔（「嗯？」「在呀，有什么事吗？」） |
| B | system 人设 + 加「别用客服腔」，t0.8 | 1/6 客服腔 |
| C | 同上，t0.3 | 全部在角色内 |
| D | **人设拼进 user** + 加指令，t0.3 | 6/6 在角色内，且出现「神明大人」「八千代」 |
| E/F/G | 人设拼进 user，t1.0 / 0.8 / 0.5 | 各组 6/6 全部在角色内 |

**结论：关键变量是注入位置，不是温度。** 人设放 system 时 LongCat-2.5-Preview 会无视它；拼进 user 消息后，即使 t=1.0 也稳定在角色内。

## 改动

- `core/poke.py`：`build_poke_prompt()` 新增 `persona` 参数；任务正文加一句「用你自己的口吻、自己的自称和口头禅应一句，别用客服腔，别用通用客套话」；persona 非空时前置 `{persona}\n\n——按上面这个角色——\n{body}`。
- `main.py`：`_poke_text` 调用 `build_poke_prompt(..., persona=persona)`；`provider.text_chat(prompt=prompt)` 不再传 `system_prompt`（避免双重注入）。
- `metadata.yaml`：0.2.18 → 0.2.19。

## 方法教训

- **「带了人设」不等于「模型会用人设」**：注入位置（system vs user）在这个模型上直接决定成败。以后凡是短任务 + 长人设的调用，默认把人设拼进 user 消息。
- **对照实验比读代码快**：直接打模型接口做 A/B，比反复读框架源码更快定位「模型为什么不听话」。
- **采样要够**：单次调用会误导——第一次 A 组复现了症状，重跑一次却出了角色内结果。必须多采样看比例。
