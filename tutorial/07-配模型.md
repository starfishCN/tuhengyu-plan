# 07 · 给它一个脑子

链路已经通了，但机器人还是个哑巴 —— 它不知道该说什么。

这一篇给它接一个大模型。

---

## 一、先选一个模型服务

**关键限制：如果你的服务器在国内，很多国外模型 API 是连不上的。**

| 服务商 | 国内能不能直连 | 说明 |
|---|---|---|
| **DeepSeek** | ✅ 能 | 便宜，中文好，**推荐先试这个** |
| **阿里通义千问** | ✅ 能 | 有免费额度 |
| **硅基流动** | ✅ 能 | 聚合了很多开源模型 |
| **LongCat（美团）** | ✅ 能 | 也是国内可直连 |
| OpenAI / Claude | ❌ 连不上 | 别浪费时间 |
| 智谱 / Kimi | ⚠️ 实测超时 | 有时能通，不一定 |

**建议：先用 DeepSeek。** 便宜、稳定、中文不错。

> 你也可以先自己测一下：
>
> ```bash
> curl -s -o /dev/null -w "%{http_code}" --max-time 10 https://api.deepseek.com
> ```
>
> 返回 `401` 或 `200` 就是通的（401 表示「需要密钥」，是正常的）。
> 返回 `000` 就是连不上。

---

## 二、去服务商拿一个 API Key

以 DeepSeek 为例：

1. 打开 `platform.deepseek.com`，注册登录
2. 找到 **「API Keys」**
3. 点 **「创建 API Key」**
4. **立刻复制那串 key** —— 只显示一次
5. 往账户里充点钱（10 块钱能用很久）

其他服务商流程类似。

> ⚠️ **这串 key 等于钱。** 别发给别人，别传到公开仓库。
> 万一泄露了，去服务商后台立刻撤销。

---

## 三、在 AstrBot 里配置

打开 AstrBot 控制台。

1. 找到 **「模型提供商」/「服务提供商」/「Provider」** 这类入口
2. 点 **「新增」**
3. **类型** 选 **`openai_chat_completion`**
   （意思：用 OpenAI 那套通用接口格式，大多数国内服务商都兼容）

### 填参数（以 DeepSeek 为例）

| 配置项 | 填什么 |
|---|---|
| **API Base / 接口地址** | `https://api.deepseek.com/v1` |
| **API Key** | 你刚复制的那串 |
| **模型名** | `deepseek-chat` |
| **超时** | `120` |

保存，**启用**。

### 常见服务商的地址对照

| 服务商 | API Base | 常用模型名 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 见官网模型列表 |
| LongCat | `https://api.longcat.chat/openai/v1` | `LongCat-2.5-Preview` |

> ⚠️ **地址末尾的 `/v1` 通常不能省。** 少了它可能报 404。

### 设为默认

如果加了好几个，把想用的那个**设为默认**（或者在每个聊天场景里指定）。
不然机器人不知道用哪个。

---

## 四、⚠️ 关于「推理模型」的坑

有些新模型是**推理模型** —— 它在回答之前会先「想」一段。

这有个副作用：**它会消耗额外的额度**，如果限制的回复长度太小，
可能「想」就把额度用完了，导致**回复是空的**。

**表现**：收到消息但你这边什么都没收到，日志里 `finish_reason` 是 `length`。

**解决**：

- 换一个普通模型（如 `deepseek-chat`）
- 或者调大回复长度上限

> 一般情况下不用管这个。**如果遇到「机器人收到消息但不回复」，
> 又确认链路是通的，就怀疑它。**

---

## 五、✅ 验收：发一条消息试试

**这是整个项目最重要的一次验收。**

1. 用**另一个 QQ**（不是机器人那个号），给机器人发：

   ```
   在吗
   ```

2. 等几秒。

3. **机器人应该回你。**

### 成功的样子

```
你：  在吗
机器人：在的！有什么可以帮你的吗？😊
```

**第一次看到机器人回你，就是整个项目跑通了。**

### 去哪里确认

| 看哪里 | 应该看到 |
|---|---|
| **AstrBot 日志** | 收到消息的记录 + 「准备发送」的记录 |
| **SnowLuma 日志** | 收到消息的记载 + 「发送」的记载 |
| **两边的记录** | 时间戳几乎一致 |

如果机器人回了，但你不满意它说话的方式（太像客服），
那是**人设**的问题 —— 第 08 篇和 10 篇解决。

---

## 六、没回复怎么办

按顺序排查：

| 检查 | 怎么看 |
|---|---|
| 1. 链路还活着吗 | 两个控制台是不是都显示「已连接」 |
| 2. 模型配了吗 | AstrBot 里有没有「启用」的 provider |
| 3. key 对吗 | 去服务商后台看看有没有调用记录 / 余额够不够 |
| 4. 服务器能连服务商吗 | 用第一节的 curl 命令测 |
| 5. 日志说了什么 | **AstrBot 日志是最终答案**，看它报什么错 |

**90% 的问题是「key 错了」或「地址少了 /v1」。**

---

## 完成检查

| 检查项 | 应该看到 |
|---|---|
| 模型服务商 | 已注册，有 key，有余额 |
| AstrBot provider | 已添加、已启用、已设默认 |
| **发消息测试** | ✅ **机器人回复了** |
