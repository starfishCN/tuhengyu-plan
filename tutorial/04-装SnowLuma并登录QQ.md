# 04 · 装 SnowLuma 并登录 QQ

这一篇是整个教程里**最有存在感**的一步 —— 你会亲眼看到服务器的桌面上，
一个 QQ 自己启动了，然后你扫码把它登上去。

---

## 一、③ 安装 SnowLuma

回到面板，点 **「③ 安装 SnowLuma」**。

**这一步最久**，因为它要下载一个几百 MB 的镜像（内含真实的 QQ 客户端）。
**耐心等，别中途刷新页面。**

成功后，日志里会出现容器的启动信息。

### 它装了什么

| 内部端口 | 用途 |
|---|---|
| 6081 | **远程桌面**（noVNC）—— 用来看和操作服务器上的 QQ 窗口 |
| 5099 | SnowLuma 自己的控制台 |
| 3000 / 3001 | 留给 AstrBot 连接用的接口 |

---

## 二、配端口映射（NAT 型机器必看）

如果你在 01 篇确认自己是 NAT 型机器，**现在去服务商控制台加两条映射**：

| 内部端口 | 外部端口（自己定） | 用途 |
|---|---|---|
| **6081** | 例：`50506` | 远程桌面 |
| **5099** | 例：`50507` | SnowLuma 控制台 |

> ⚠️ **内部端口一定别填错。** 比如 6081 填成 6018，就会连不上，
> 而且报错信息很含糊，很难查。

**有独立公网 IP 的可以跳过这一步。**

---

## 三、找到密码

**这一步面板替你做。**

回到面板，往下找到折叠区 **「找不到密码？点这里读初始凭据」**，点开，
再点 **「读取 / 刷新」**。稍等一两秒，会列出：

| 服务 | 显示什么 |
|---|---|
| 远程桌面 noVNC | 你自己的密码 |
| AstrBot 控制台 | 初始密码 |
| SnowLuma 控制台 | 初始密码 |

**每行右边有个复制按钮**，点一下就能复制。

> ⚠️ **读到的都是「初始密码」。** 如果你之后改过密码，这里显示的是旧值。
> 页面上也写了这句提示 —— 别把它当「当前密码」。

### 想手动查也行

**远程桌面密码**（存在容器的环境变量里，最稳定）：

```bash
docker inspect snowluma --format '{{range .Config.Env}}{{println .}}{{end}}' 2>/dev/null | grep '^VNC_PASSWD='
```

输出形如 `VNC_PASSWD=tuhengyu2026`，等号后面就是密码。

**AstrBot 控制台密码**：

```bash
docker logs astrbot 2>&1 | grep 'Initial password' | tail -n 1
```

输出形如 `➜  Initial password: Nrvn5CC...`。

**SnowLuma 控制台密码**：

```bash
docker logs snowluma 2>&1 | grep 'initial credentials' | tail -n 1
```

输出形如 `initial credentials: user=admin password=aa660de...`。

### ⚠️ 两个必须知道的事

**一、日志里的密码只在「第一次启动」时打印。**

如果命令没输出，说明容器不是全新的了。

**二、SnowLuma 的初始密码会变。**

日志里可能出现这一句：

```
WARN [WebUI.Auth] previous bootstrap password was never rotated; regenerated a new one
```

意思是：**上次生成的初始密码你没改，这次它换了一个新的。**

**所以：登录之后第一时间改密码。** 改完就记在自己那儿，别依赖日志。

---

## 四、打开远程桌面

浏览器访问：

```
http://你的IP:50506
```

> `50506` 是你自己映射的外部端口。

会出现一个远程桌面 —— **里面应该已经开着一个 QQ 的登录窗口了**。

### 如果提示要密码

输入刚才取到的**远程桌面密码**。

### 如果连不上

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面打不开 | 端口没映射 / 映射错了 | 回控制台检查，**内部必须是 6081** |
| 打得开但是黑屏 | 桌面还没启动完 | 等 1～2 分钟再刷新 |
| 提示密码错误 | 密码输错或抓错了 | 重新执行取密码的命令 |
| 一直转圈 | 网络慢 | 等 |

---

## 五、扫码登录

在远程桌面里，你会看到 QQ 的登录界面（通常已经显示了二维码）。

1. 用**手机 QQ** 扫这个二维码
   - 打开手机 QQ → 右上角「+」→ **扫一扫**
2. 手机上会问「是否在电脑上登录」→ 确认
3. 远程桌面里的 QQ 就登进去了

### ⚠️ 关于扫码

- **用你要当机器人的那个号扫**（小号！不是你的主号）
- 如果手机上已经登录着这个号，QQ 可能会提示「已在其他设备登录」，
  按提示切换即可
- **别关掉远程桌面的浏览器标签** —— 后面可能还要用它处理验证

### 登录成功的样子

远程桌面里能看到 QQ 主界面，左边是好友列表，**这就成了**。

**这时候那台服务器上，已经有一个真实的 QQ 在跑。**

---

## 六、看一眼 SnowLuma 控制台（可选）

访问 `http://你的IP:50507`，用上面取到的控制台密码登录。

这里能看到：

- OneBot 的连接状态（**现在是「未连接」，正常**，还没配 AstrBot）
- 消息日志
- **左侧的「日志」和「实时事件流」** —— 排错时非常有用

**记住这个页面。** 后面链路出问题时，就看这里的日志。

---

## 完成检查

| 检查项 | 应该看到 |
|---|---|
| SnowLuma 容器 | 运行中 |
| 远程桌面能打开 | ✅ |
| QQ 已登录 | 远程桌面里能看到 QQ 主界面 |
| SnowLuma 控制台 | 能打开，显示「未连接」 |
