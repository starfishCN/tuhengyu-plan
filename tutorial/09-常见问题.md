# 09 · 常见问题

先记住一条：不要连续重复点击。先看面板日志最后 20 行。

## 面板打不开

- 地址使用 `http://`，不是 `https://`。
- 云安全组放行面板外部端口。
- SSH 执行 `systemctl status tuhengyu-panel`。
- 查看 `journalctl -u tuhengyu-panel -n 80 --no-pager`。

## 安装命令无法开始

新版入口本身会尝试 jsDelivr、GitHub raw、Gitee raw。三者都失败时，通常是服务器没有可用出口。

处理顺序：

1. 换一条服务器线路。
2. 确认系统软件源可访问。
3. 手动上传 `bootstrap.sh` 再执行。

## 自动部署失败

只处理日志最后一条 `!!`：

| 最后提示 | 处理 |
|---|---|
| 没有可用 Docker 镜像源 | 换线路、配置代理或镜像中转 |
| venv / ensurepip | 等脚本自动安装，仍失败再补 `python3-venv` |
| pip Network is unreachable | 脚本会切换国内源；仍失败则换线路 |
| Docker Hub / CDN timeout | 公共镜像入口通不代表大文件可达，使用代理或中转 |
| AstrBot pull 失败 | 查看完整日志，确认 DaoCloud 兜底是否成功 |
| SnowLuma pull 卡住 | 换线路或使用镜像中转 |

## 如何重新执行

面板任务结束后才能重试。不要同时点多个按钮。重复执行会复用已有容器和数据，若容器状态异常，先查看：

```bash
docker ps -a
docker logs --tail 100 astrbot
docker logs --tail 100 snowluma
```

## 忘记面板密码

按当前安装目录处理，先不要删除整个目录。旧版和新版认证文件可能不同，优先通过 systemd 配置与面板日志定位。删除认证文件前先备份。

## 端口怎么分

| 端口 | 用途 | 建议 |
|---|---|---|
| 8080 | 部署面板 | 测试时开放，长期限制来源 |
| 6081 | noVNC | 只在扫码时开放 |
| 5099 | SnowLuma 控制台 | 限制来源 |
| 6185 | AstrBot 控制台 | 限制来源 |
| 6199 | 容器内部通信 | 不映射公网 |

## 入口通但镜像本体超时

Docker registry 返回 401 只说明入口能回应，不说明大文件 CDN 可达。此时继续换公共源通常无效。改用有国际出口的机器、为 dockerd 配代理，或在另一台机器 `docker save` 后传输，再 `docker load`。

## `/sdcard` 权限测试失败

安卓或 FUSE 环境不保留标准 POSIX 权限位。若同一代码在 `/tmp` 正常，在 `/sdcard` 失败，这是测试环境限制，不代表 VPS 代码失败。
