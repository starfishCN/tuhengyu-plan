# 09 · 常见问题

卡住了先来这里找。**按现象查。**

---

## 面板相关

### 面板打不开 / 一直转圈

| 检查 | 怎么做 |
|---|---|
| 端口映射对不对 | 内部是 `8080`，外部是你自己定的。**别把内部端口填成外部那个** |
| 服务起来了吗 | 服务器上执行 `systemctl status tuhengyu-panel` |
| 防火墙 | 云厂商控制台的「安全组」可能要放行端口 |
| 是不是 HTTPS 的问题 | 用 `http://`，不是 `https://` |

### 面板能打开但按钮点了没反应

看页面下方的**日志窗口**。所有动作的输出都在那里。

### 首次登录被要求改密 / 忘了面板密码

**首次登录必须改密** —— 初始密码是安装时随机生成的临时密码，
只在安装终端打印过一次，用过就废。

忘了自己改的密码，把密码文件删掉即可回到初始密码：

```bash
rm /opt/tuhengyu-panel/.panel_auth.json
systemctl restart tuhengyu-panel
```

初始密码在 `/etc/systemd/system/tuhengyu-panel.service` 里
`PANEL_PASS=` 那一行。登进去后**还会再要求你改一次密**。

---

### 提示「有任务正在执行，请等它结束」

面板同一时间只能跑一个任务。**等上一个跑完再点。**

## 安装相关

### ② 安装 Docker 失败

**最常见原因：下载源连不上。**

1. 展开「网络源」折叠区
2. 点「一键测速并自动选优」
3. 点「应用选中的镜像加速」
4. 再点一次 ②

还是不行的话，看日志里的具体报错 —— 可能是系统版本不对
（必须是 Ubuntu 22.04 / 24.04）。

---

### 装 Docker 的顺序不能反

**先装本体，再配镜像源。** 顺序反了不会报错，但配的那份文件一点用都没有。

```bash
apt-get update && apt-get install -y docker.io
systemctl enable --now docker
```

装完再写加速配置、再 `systemctl restart docker`。

---

### 判断这台机器能不能拉镜像（两条命令）

**第一条：Docker Hub 通不通**

```bash
curl -s -o /dev/null -w '%{http_code}\n' --max-time 15 https://registry-1.docker.io/v2/
```

| 返回值 | 含义 |
|---|---|
| `401` | 通，正常（匿名访问本来就要求认证） |
| `200` / `403` | 通（被代理或镜像源改写了应答） |
| `000` | 连不上 / DNS 失败 / 被墙 |
| 无输出、卡满 15 秒 | 超时，不通 |

**第二条：加速器还活着吗**

```bash
for u in https://docker.m.daocloud.io https://docker.1ms.run https://docker.xuanyuan.me; do
  printf '%-38s ' "$u"; curl -s -o /dev/null -w '%{http_code}\n' --max-time 10 "$u/v2/"
done
```

回 `401` 或 `200` 的可用，`000` 的已死。**这份候选源会过期，以你自己跑的结果为准。**

---

### 配置镜像加速（三步）

```bash
# 1) 写配置
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{"registry-mirrors": ["https://<上一步跑通的地址>"]}
EOF

# 2) 生效
systemctl restart docker
docker info | grep -A3 'Registry Mirrors'    # 能看到地址即生效

# 3) 验收
docker pull hello-world
```

`hello-world` 能拉下来才算过。拉不动就换下一个地址，从头再来。

> ⚠️ 别用花括号引号直接粘到 PowerShell / VNC 里，剪贴板会吃字符，
> 报 `unknown --write-out variable` 就是被截断了。用单引号写法。

### 🔥 最坑的一条：注册表入口通，镜像本体拉不动

```
现象：docker pull 卡在 Pulling，半天不动，最后报
     dial tcp <IP>:443: i/o timeout
```

**原因**：加速器的「入口」在国内（能回 `401`），
但**大文件本体托管在境外 CDN**（Cloudflare 等）。
入口通、本体不通，看起来就像加速器坏了 —— 其实换哪个加速器都一样。

**判断方法**：看报错里超时的域名。如果域名的解析 IP 落在 Cloudflare，
基本可以确定是这条路。

**三条出路：**

| 方案 | 说明 |
|---|---|
| 换机器 | 选**有国际出口**的线路。这是唯一的根治办法 |
| 给 Docker 配代理 | 你手上得有可用代理 |
| 手动中转 | 在别的机器 `docker save` 导出成 tar，传到这台 `docker load` |

> ⚠️ **给 Docker 配代理，不是 `export http_proxy`。**
> 那是给 shell 的，`dockerd` 看不见。必须配给 Docker 服务本身。

### SSH 连不上（按报错对号）

| 报错 | 什么意思 | 怎么修 |
|---|---|---|
| `Bad port` | 端口参数里有非法字符 | 端口只能纯数字，别带空格 / 掩码点 / 中文标点 |
| `Could not resolve hostname` | 地址没被认出来 | 别混进中文句号「。」、全角字符；别把面板的掩码（`1.2.x.x`）一起复制；`:端口` 不能跟在 `@` 后 |
| `Connection timed out` | 端口没通 | 面板里的映射没开，或端口已经变了 |
| `Permission denied` | **网络已通，只是密码错** | 在云厂商控制台重置 root 密码；核对用户名是不是 `ubuntu` |

最后一条最容易误判：能收到 `Permission denied`，说明 TCP 已经连上，
前面所有网络问题都不存在，只剩凭据。

### ③ 安装 SnowLuma 卡住 / 镜像拉不动

**这是最经典的坑。**

```
现象：日志卡在 Pulling / Downloading，半天不动
```

**解决：**

1. 回到「网络源」折叠区，**重新测速并应用镜像加速**
2. 如果还不行，说明这台机器确实连不上外网仓库

**实在拉不动，有三条路：**

| 方案 | 说明 |
|---|---|
| 换机器 | 换个区域试试，同一家厂商不同区域可能完全不同 |
| 找中转源 | 用国内的镜像站（面板里的候选源就是干这个的） |
| 手动传镜像 | 在别的机器上下载好，`docker save` 导出，传到这台再 `docker load`（高级操作） |

> **经验**：不要在一台拉不动的机器上死磕。**换一台按小时计的机器试试**
> 往往比折腾半天快。

---

### 内存不够 / 服务自己崩了

```
现象：容器跑一会就退出、ssh 卡顿、内存告警
```

两个容器加一个真实 QQ 客户端，**内存比较吃紧**。

```bash
free -h
```

看 `available` 那一列。低于 300 MB 就很危险了。

**解决：**

- 升级内存（正规方案）
- 加 Swap（临时方案）：[见下](#加-swap)
- 关掉不用的服务

---

### 加 Swap

连上服务器：

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h
```

最后一行应该能看到 Swap 那栏有 2G。

## QQ 相关

### 远程桌面打不开

```
现象：浏览器访问 50506 无反应
```

| 检查 | 说明 |
|---|---|
| 端口映射 | **内部必须是 6081**。填成 6018 之类会连不上 |
| `Server: WebSockify` | 用浏览器 F12 看响应头，有这行说明服务正常 |
| 容器活着吗 | `docker ps \| grep snowluma` |

### 远程桌面里没有 QQ 窗口

- 等 1～2 分钟，首次启动慢
- 看日志：`docker logs snowluma 2>&1 | tail -50`

### 扫码后登录失败

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示「版本过低」 | QQ 版本被限制 | 等 SnowLuma 更新 / 换新版本镜像 |
| 提示「环境异常」 | 风控 | **换号**或换机器 IP。新号先在手机上正常用几天再挂 |
| 反复要求验证 | 风控 | 同上。也可能是同 IP 上挂过太多号 |
| 扫码没反应 | 二维码过期 | 点一下二维码刷新 |

### QQ 掉了 / 要重新扫码

正常现象。**看远程桌面里 QQ 是不是弹了登录框**，重新扫一次即可。

如果**频繁**掉线：机器 IP 可能被风控了，考虑换机器。

## 链路相关

### 两边都配了，但连不上

**按这个顺序查：**

1. **容器在一个网络里吗**

   ```bash
   docker exec snowluma ping -c 2 astrbot
   ```

   不通就：

   ```bash
   docker network connect snowluma_default astrbot
   ```

2. **URL 对吗**

   `ws://astrbot:6199/ws` —— **末尾的 `/ws` 不能少**。

3. **Token 一致吗**

   两边逐字符对一遍。**大小写、空格都算。**

4. **AstrBot 端口在监听吗**

   ```bash
   docker exec astrbot netstat -tln 2>/dev/null | grep 6199
   ```

   > 注意：**在宿主机上执行 `ss -tn | grep 6199` 是看不到东西的**，
   > 这是正常的 —— 容器之间的通信不走宿主机的网络栈。
   > **必须进容器里看。**

5. **重启试试**

   ```bash
   docker restart astrbot snowluma
   ```

### 昨天还好好的，今天断了

**八成是 QQ 掉线了。** 去远程桌面看看 QQ 还在不在。

链路断了一般是这两个原因：QQ 掉线 / 某个容器重启。

## 模型相关

### 机器人收到消息但不回复

**按顺序排：**

1. **链路是否还在** —— 两个控制台都显示已连接吗
2. **模型是否启用** —— AstrBot 里那个 provider 是不是「启用」状态
3. **key / 余额** —— 服务商后台看调用记录和余额
4. **地址对不对** —— 末尾的 `/v1` 别少
5. **看 AstrBot 日志** —— 它会告诉你具体原因

### 回复是空的 / 只说一半

**怀疑是「推理模型」吃掉了额度**（见 07 篇第四节）。

换一个普通模型试试。

### 回复特别慢

- 模型本身慢（有些模型第一次调用要等）
- 服务器网络慢
- **正常范围**：3～10 秒。超过 30 秒要查原因

## 插件相关

### `[图恒宇测试` 没反应

| 检查 | 说明 |
|---|---|
| 斜杠加了吗 | **必须**是 `/图恒宇测试` |
| 插件加载了吗 | `docker logs astrbot \| grep 图恒宇` |
| 日志里有报错吗 | 看 `[图恒宇]` 开头的行 |

### 发空间失败

**最常见的是 `code: -3000`**（提示「请先登录空间」）。

**原因：** 取 cookie 的时候没指定空间域。

**说明：** 插件已经处理了这个问题（取 cookie 时带了
`domain=user.qzone.qq.com`）。**如果你看到 -3000，可能是：**

- QQ 掉线了 → 重新登录
- 接口改了 → **空间接口是逆向的，官方随时可能改**，改了插件就失效

**插件遇到 -3000 会自动清掉缓存的 cookie**，下次重新取。可以先重试一次。

### 内容和预期不一样

插件默认语气是**中性**的。想要有个性，得配 `persona_prompt`（人设）。
见 08 篇和 10 篇。

## 其他

### 找不到密码 / 密码在哪

**面板能直接读。** 展开首页的 **「找不到密码？点这里读初始凭据」**，点 **「读取 / 刷新」**。

会列出远程桌面、AstrBot、SnowLuma 三处密码，每行带复制按钮。

命令行查（原理与注意事项详见 04 / 05 篇）：

```bash
# 远程桌面（最稳，存在环境变量里）
docker inspect snowluma --format '{{range .Config.Env}}{{println .}}{{end}}' | grep '^VNC_PASSWD='

# AstrBot 控制台
docker logs astrbot 2>&1 | grep 'Initial password' | tail -n 1

# SnowLuma 控制台
docker logs snowluma 2>&1 | grep 'initial credentials' | tail -n 1
```

> ⚠️ 后两条读的是**初始密码**，改密后失效。
>
> ⚠️ **SnowLuma 的初始密码会变** —— 没改密的话，重启会重新生成一个。

### 装面板时报 `ensurepip is not available` / 建 `.venv` 失败
**原因**：系统没装 `python3-venv`（不少精简版 VPS 镜像默认不带）。
**手动修**（一条命令，然后重跑安装脚本）：
```bash
apt-get update -y && apt-get install -y python3-venv
```
Debian/Ubuntu 若提示找不到包，改装版本化的：`python3.12-venv`（数字换成 `python3 -V` 显示的版本）。
> 新版 `setup.sh` 已自带这一步（创建失败会自动装再重试）；旧版需手动执行上面命令。

### 一键命令拉不下脚本（curl 报 451 / 空内容）
Gitee 对 `.sh` 文件的 raw 下载会风控（返回 `451`），这是仓库侧的限制，不是你机器的问题。
**备用命令**（按顺序试）：
```bash
# ① Gitee API 取文件（国内可达，只依赖 python3；无国际出口的机器用这条）
python3 -c "import urllib.request,json,base64;d=json.load(urllib.request.urlopen('https://gitee.com/api/v5/repos/starfishCN/tuhengyu-plan/contents/setup.sh?ref=main'));open('/tmp/setup.sh','wb').write(base64.b64decode(d['content']))" && bash /tmp/setup.sh
# ② jsDelivr（镜像 GitHub，国内多数可达）
curl -fsSL https://cdn.jsdelivr.net/gh/starfishCN/tuhengyu-plan@main/setup.sh | bash
# ③ GitHub 直连（需能访问 GitHub）
curl -fsSL https://raw.githubusercontent.com/starfishCN/tuhengyu-plan/main/setup.sh | bash
```
> 无国际出口的机器（PyPI / Docker Hub 都不通）直接用 ①。
> 若报 `TypeError: list indices must be integers...`：你用的是旧命令里的 `install.sh`，该文件已改名 `setup.sh`，旧路径不存在时 Gitee API 返回的是目录列表。
### 装面板时 pip 报 `Network is unreachable`（Errno 101）
机器的出口**连不上 PyPI**（新买的云实例常见，和 Docker 拉不动同因）。
**手动修**（用国内镜像装依赖，再重跑安装脚本）：
```bash
/opt/tuhengyu-panel/.venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -U pip
/opt/tuhengyu-panel/.venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r /opt/tuhengyu-panel/requirements.txt
```
或一句话设全局镜像：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`。
> 新版 `setup.sh` 已自带这一步（直连失败自动换清华/阿里镜像重试）；旧版需手动执行上面命令。

### 怎么重启所有服务

```bash
docker restart astrbot snowluma
systemctl restart tuhengyu-panel
```

### 怎么看某个容器的日志

```bash
docker logs astrbot 2>&1 | tail -50        # 最后 50 行
docker logs astrbot -f                      # 实时滚动（Ctrl+C 退出）
docker logs snowluma 2>&1 | grep -i error   # 只看错误
```

### 怎么更新

**插件**：重新 `git clone` 覆盖，然后 `docker restart astrbot`

**AstrBot / SnowLuma**：面板里重新点安装按钮（会拉新镜像）

> ⚠️ **更新前先备份。** 特别是配置文件（`cmd_config.json`）和插件配置。

## 还是不行

**搜集这三样东西**，再去提问或搜索：

1. **完整报错原文**（别截断，别转述）
2. **用的是哪一步**（比如「③ 装 SnowLuma 时」）
3. **环境信息**：`uname -a`、`free -h`、`docker ps` 的输出

**报错原文是最重要的。** 「不行」「报错了」这种描述，谁也帮不了你。
