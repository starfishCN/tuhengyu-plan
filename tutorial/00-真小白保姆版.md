# 图恒宇计划 · 真小白保姆版

这篇只给第一次接触服务器、Docker、AstrBot 的人看。

你不需要先学懂 Docker，也不需要自己判断该安装什么。全程只做三类动作：复制命令、点击按钮、把屏幕上最后的错误发出来。

## 先看最终流程

按这个顺序做，不要跳步：

1. 买一台全新的 Ubuntu 服务器。
2. 用 SSH 登录服务器。
3. 复制本篇的安装命令。
4. 浏览器打开面板。
5. 点击「开始自动部署」。
6. 用手机 QQ 扫码登录远程桌面里的 QQ。
7. 配置模型。
8. 发一条消息测试。

部署面板只是安装入口。图恒宇计划插件才是核心，它负责作息、空间、表情包、好感度、戳一戳和群聊行为。

## 第一步：先确认是不是 NAT 服务器

这是最容易让新手卡住的一步。

购买服务器时，先看服务商写的是哪一种：

| 类型 | 特征 | 能否直接用 |
|---|---|---|
| 独立公网 IPv4 | 有独立公网 IP，端口通常直接开放 | 可以直接用 |
| NAT VPS / 端口转发 VPS | 多台机器共用一个公网 IP，需要服务商分配外部端口 | 可以用，但必须配置端口映射 |
| 只有 IPv6 | 没有公网 IPv4 | 新手不建议使用 |

**NAT 不是不能装。NAT 的意思是：服务器内部端口和你浏览器访问的外部端口不是同一个。**

向服务商确认并记录：

1. 公网 IP。
2. SSH 的外部端口。
3. SSH 映射到服务器内部的 `22` 端口。
4. 面板 `8080`、noVNC `6081`、SnowLuma `5099`、AstrBot `6185` 是否允许映射。
5. 每个外部端口分别映射到哪个内部端口。

如果服务商只给你一个 IP，没有给端口转发列表，先不要买。没有 SSH 外部端口，你连不上服务器；没有面板端口，你打不开面板。

**注意：NAT 端口映射和 Docker 镜像下载是两回事。**端口映射只决定别人能否访问你的服务，不会让服务器获得 Docker Hub 或 CDN 的下载线路。

购买时再看这张表：

| 项目 | 建议 |
|---|---|
| 系统 | Ubuntu 22.04 或 24.04 |
| 架构 | x86_64 |
| CPU | 2 核或以上 |
| 内存 | 4G 或以上 |
| 硬盘 | 30G 或以上 |
| 账号 | 建议准备 QQ 小号 |

买好后记下：公网 IP、SSH 外部端口、用户名、密码和端口映射表。

不要使用主 QQ 号。QQ 非官方接口有风控和限制风险。

## 第二步：连接服务器

在手机或电脑上打开 SSH 工具，填写：

- 地址：服务器公网 IP
- 端口：服务商给你的 SSH 端口，常见是 22
- 用户名：通常是 `root`
- 密码：服务器密码

连接成功后，屏幕上通常会出现：

```text
root@服务器:~#
```

看到这个提示，就说明已经进入服务器。

如果你的用户名是 `ubuntu`，也可以先继续。后面的命令如果提示权限不足，再在命令前加 `sudo`，或让服务商切换到 root。

## 第三步：安装面板

把下面整段命令完整复制。必须从 `if` 开始，一直复制到最后的 `exit 1`。不要只复制其中一行。

```bash
if ! command -v curl >/dev/null 2>&1 && ! command -v wget >/dev/null 2>&1 && ! command -v python3 >/dev/null 2>&1; then
  export DEBIAN_FRONTEND=noninteractive
  apt-get update -y && apt-get install -y curl ca-certificates || { echo "无法自动补齐下载工具" >&2; exit 1; }
fi
fetch() {
  if command -v curl >/dev/null 2>&1; then curl -fL --connect-timeout 10 --max-time 60 "$1" -o /tmp/tg-bootstrap.sh
  elif command -v wget >/dev/null 2>&1; then wget -T 60 -O /tmp/tg-bootstrap.sh "$1"
  else python3 -c 'import sys,urllib.request; urllib.request.urlretrieve(sys.argv[1], "/tmp/tg-bootstrap.sh")' "$1"
  fi
}
for u in \
  https://cdn.jsdelivr.net/gh/starfishCN/tuhengyu-plan@main/bootstrap.sh \
  https://raw.githubusercontent.com/starfishCN/tuhengyu-plan/main/bootstrap.sh \
  https://gitee.com/starfishCN/tuhengyu-plan/raw/main/bootstrap.sh; do
  if fetch "$u" && grep -q '^#!/usr/bin/env bash' /tmp/tg-bootstrap.sh; then
    bash /tmp/tg-bootstrap.sh && exit 0
  fi
  rm -f /tmp/tg-bootstrap.sh
done
echo "所有入口均不可用，请检查网络或换服务器线路。" >&2
exit 1
```

按回车后等待。不要在命令运行时再次粘贴，也不要因为几分钟没有新字就强行中断。

### 安装成功的样子

最后会显示类似内容：

```text
面板地址：http://你的IP:8080
账号：admin
初始密码：一串随机字符
```

立刻把初始密码复制到安全的地方。不要发到群里。

### 这里报错怎么办

只按下面对应处理：

| 屏幕现象 | 你该做什么 |
|---|---|
| `451`、Gitee raw | 不要改文件名，重新复制本篇整段命令，命令会自动换 jsDelivr、GitHub、Gitee |
| `list indices must be integers` | 你用了旧命令，重新复制本篇整段命令 |
| `install.sh` | 你用了旧教程，重新复制本篇整段命令 |
| `Network is unreachable`、`Errno 101` | 服务器出网不通，先换服务器线路；不要不停重试 |
| `无法自动补齐下载工具` | 系统软件源也不通，换一台服务器或换线路 |
| 其他红色错误 | 不要删除文件，复制最后 20 行保存，先看本篇末尾的“真的失败了怎么办” |

## 第四步：打开面板

用浏览器打开：

```text
http://你的服务器IP:8080
```

把“你的服务器IP”替换成真实 IP。使用 `http://`，不要写成 `https://`。

用户名填写：

```text
admin
```

密码填写刚才终端显示的随机初始密码。第一次登录会要求你改密码。改完后记住新密码。

### 浏览器打不开

在 SSH 里逐行执行：

```bash
systemctl status tuhengyu-panel --no-pager
```

如果看到 `active (running)`，说明面板在运行，通常是云服务器安全组没有放行 8080。去服务商控制台添加入站规则：TCP、端口 8080、来源先填你的公网 IP。

如果不是 `active`，再执行：

```bash
journalctl -u tuhengyu-panel -n 80 --no-pager
```

把最后 20 行保存下来，不要自行删除 `/opt/tuhengyu-panel`。

## 第五步：只点击一个按钮

登录面板后，找到：

```text
开始自动部署
```

只点击一次，然后等待。

面板会自动按这个顺序工作：

1. 检查环境。
2. 安装 Docker。
3. 测速并选择可用镜像源。
4. 安装 AstrBot。
5. 安装 SnowLuma。
6. 安装图恒宇计划插件。

你不需要自己安装 Docker、Python、git、pip、AstrBot、SnowLuma，也不需要手动安装插件。

不要点击“高级模式”里的单步按钮。那是排错用的。

### 部署成功的样子

日志最后出现自动部署完成，且能看到 AstrBot、SnowLuma 和插件已经启动。

这只代表软件安装完成。此时还没有登录 QQ，也还没有配置模型。

### 部署中途失败

先不要重装、不要删除容器、不要连续点击。

只看日志最后一条带 `!!` 的错误：

| 错误 | 处理 |
|---|---|
| `ensurepip is not available` | 脚本会自动安装 venv；等待失败后再重试主按钮 |
| pip `Network is unreachable` | 换服务器线路或配置代理 |
| 没有可用 Docker 镜像源 | 换服务器线路；公共源全部不可用时继续点击没有意义 |
| Docker Hub / CDN timeout | 镜像大文件线路不通，换线路或使用镜像中转 |
| AstrBot pull 失败 | 先重试一次；仍失败就保存完整日志 |
| SnowLuma pull 卡住 | 等待当前任务结束后换线路，不要重复创建容器 |

## 第六步：登录 QQ

自动部署完成后，回到面板，找到凭据区域，点击：

```text
读取 / 刷新
```

找到 noVNC 或远程桌面的地址、端口和密码。

在浏览器打开它。你会看到服务器里的远程桌面，里面有 QQ 登录窗口。

用手机 QQ 扫码登录。建议使用机器人小号。

看到 QQ 主界面，说明登录成功。不要关闭 QQ，不要停止 SnowLuma 容器。

### 远程桌面打不开

- 面板显示的外部端口才是浏览器要访问的端口。
- 内部端口通常是 `6081`。
- 检查云安全组是否放行对应外部端口。
- 黑屏先等 1–2 分钟再刷新。
- 密码错误就回面板重新读取初始凭据。

## 第七步：确认 AstrBot

在面板凭据区域读取 AstrBot 控制台地址和密码。

浏览器打开地址并登录。第一次登录后立即修改密码。

如果面板读不到初始密码，SSH 执行：

```bash
docker logs astrbot 2>&1 | grep 'Initial password' | tail -n 1
```

确认两个容器都在运行：

```bash
docker ps --format '{{.Names}} {{.Status}}'
```

应该能看到：

```text
astrbot
snowluma
```

## 第八步：手动把 SnowLuma 和 AstrBot 连起来

这里必须特别说明：当前面板会自动安装两个软件，但**不会自动填写 WebSocket 配置**。这一步需要在两个网页里各填写一次。

不要把它理解成“再安装一次”。只是告诉 SnowLuma 去哪里连接 AstrBot。

### 8.1 先打开 AstrBot 的反向 WebSocket

打开 AstrBot 控制台，找到名字类似下面的位置：

```text
消息平台 / 平台 / 适配器 / Platform
```

不同版本的中文名称可能不同。找到后点击：

```text
新增 / 添加适配器
```

类型选择下面其中一个：

```text
aiocqhttp
OneBot v11
```

这两个名称在不同版本中可能指同一个适配器。

填写：

| 配置项 | 填写内容 |
|---|---|
| 连接方式 | 反向 WebSocket / Reverse WebSocket |
| 监听地址 | `0.0.0.0` |
| 监听端口 | `6199` |
| Token / 密钥 | 自己设置，例如 `tuhengyu-ws-2026` |

点击保存，并确认适配器已经启用。

Token 要先复制下来，下一步还要填到 SnowLuma。两边必须完全一样，不能多空格。

### 8.2 再打开 SnowLuma 的 WebSocket 客户端

打开 SnowLuma 控制台，找到名字类似下面的位置：

```text
连接 / OneBot / 网络配置 / WebSocket
```

点击：

```text
新增 WebSocket 客户端
```

有些版本会叫 `wsClient`、`WS 客户端` 或 `反向连接`。选“客户端”，不要选“服务端”。

填写：

| 配置项 | 填写内容 |
|---|---|
| 名称 | `wsclient-1` |
| 目标地址 / URL | `ws://astrbot:6199/ws` |
| Access Token / 访问令牌 | 填刚才 AstrBot 的 Token |
| 角色 / Role | `Universal` |
| 消息格式 | `array` 或 `数组` |
| 重连间隔 | `5000` 毫秒 |

重点检查三处：

1. 地址必须是 `ws://astrbot:6199/ws`，末尾的 `/ws` 不能删。
2. 必须写容器名 `astrbot`，不要写公网 IP，也不要写 `localhost`。
3. SnowLuma 的 Token 必须和 AstrBot 完全相同。

填写后点击保存，再启用这个 WebSocket 客户端。

### 8.3 确认连接成功

保存后等待 5–20 秒，在 SnowLuma 控制台中查看连接状态。应显示：

```text
已连接 / Connected
```

AstrBot 控制台也应显示：

```text
QQ 在线
OneBot 已连接
aiocqhttp 已连接
```

还可以用 SSH 查看日志：

```bash
docker logs --tail 100 astrbot
docker logs --tail 100 snowluma
```

两边日志都出现连接成功，才算连线完成。

### 8.4 连不上时只按这个顺序检查

| 现象 | 检查方法 |
|---|---|
| SnowLuma 一直重连 | URL 是否为 `ws://astrbot:6199/ws`，尤其检查 `/ws` |
| `connection refused` | AstrBot 适配器是否启用，端口是否填 `6199` |
| `bad address` 或找不到主机 | 两个容器不在同一个 Docker 网络 |
| 鉴权失败 | 两边 Token 逐字对比，不能有空格 |
| 显示连接但 AstrBot 无消息 | 检查适配器类型是否为 `aiocqhttp` / `OneBot v11` |

确认容器网络：

```bash
docker inspect -f '{{json .NetworkSettings.Networks}}' astrbot
docker inspect -f '{{json .NetworkSettings.Networks}}' snowluma
```

如果两个输出没有共同的网络名，把 AstrBot 接入 SnowLuma 所在网络：

```bash
docker network ls
docker network connect 网络名 astrbot
```

然后回到 SnowLuma 点击保存或重连。

`6199` 是容器内部通信端口，**NAT 和独立公网机器都不要把它映射到公网**。这一步不需要新增外部端口映射。

## 第九步：配置模型

在 AstrBot 控制台找到“模型提供商”或“Provider”。先选择一个服务器能访问的服务商。

以 DeepSeek 为例：

| 项目 | 填写 |
|---|---|
| API Base | `https://api.deepseek.com/v1` |
| API Key | 你自己的 Key |
| 模型 | `deepseek-chat` |

保存、启用、设为默认。

不要把 API Key 发给别人，也不要写进公开仓库。

## 第十步：第一次测试

用另一个 QQ 号给机器人发送：

```text
在吗
```

成功条件：机器人收到消息，并回复一条消息。

如果没有回复，按顺序检查：

1. QQ 是否已登录。
2. SnowLuma 和 AstrBot 是否显示已连接。
3. Provider 是否已启用并设为默认。
4. API Key 是否有效且有余额。
5. API Base 是否包含 `/v1`。
6. AstrBot 日志最后一条错误是什么。

## 第十一步：确认图恒宇计划插件

插件由自动部署预置，不需要从插件市场下载，也不需要手动 clone。

SSH 执行：

```bash
ls /opt/tuhengyu-panel/data/plugins/astrbot_plugin_tuhengyu
```

目录存在就说明插件文件已经在服务器上。

查看加载记录：

```bash
docker logs astrbot 2>&1 | grep -E 'astrbot_plugin_tuhengyu|生活调度器' | tail -n 20
```

如果没有记录，执行：

```bash
docker restart astrbot
```

等待 10 秒，再查看日志。

## 真的失败了怎么办

不要执行“删掉重装”这种大动作。先按下面格式收集信息：

```bash
cat /etc/os-release
docker ps -a
docker logs --tail 100 astrbot
docker logs --tail 100 snowluma
journalctl -u tuhengyu-panel -n 100 --no-pager
```

然后把以下内容发出来：

1. 你做到第几步。
2. 你刚才执行了什么操作。
3. 最后一条完整错误。
4. 上面命令的输出。

发之前删掉 IP、密码、API Key、Token 和 Cookie。

只要不是明确要做全新测试，就不要删除 `/opt/tuhengyu-panel`、Docker 卷或 QQ 登录数据。删除数据会让问题更难定位。

## 你已经完成了什么

当下面五项都满足时，基础部署完成：

- 面板可以登录。
- QQ 在远程桌面中在线。
- SnowLuma 与 AstrBot 已连接。
- 机器人能回复“在吗”。
- 图恒宇计划插件已加载。

之后再阅读 [10 · 人设、安全、备份和长期运行](10-然后呢.md)，调整 bot 的性格和生活行为。
