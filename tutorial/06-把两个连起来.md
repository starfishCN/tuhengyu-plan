# 06 · 把两个连起来

**这一篇是技术含量最高的一篇。** 慢慢来，一步一步做。

面板上第 ⑤ 个按钮写着「连线（待实现）」—— 所以我们**手动连**。
需要连上服务器敲几条命令。

---

## 先说原理（30 秒）

我们要让「手和嘴」（SnowLuma）和「大脑」（AstrBot）通上话。

通信方式叫 **反向 WebSocket**：AstrBot 开一个「门」（监听端口），
SnowLuma 主动来敲门（发起连接），敲上就通了。

```
SnowLuma  ──敲门──►  AstrBot
          ws://astrbot:6199/ws
```

所以要做两件事：

1. **AstrBot**：开门（配一个 aiocqhttp 适配器）
2. **SnowLuma**：去敲门（配一个 WebSocket 客户端）

**顺序无所谓，两边都配好才算数。**

---

## 一、让两个容器能互相找到

先做一个准备：确认两个容器在同一个网络里。

连上服务器，执行：

```bash
docker exec snowluma ping -c 2 astrbot
```

> 如果你的容器名字不是 `snowluma` / `astrbot`，用 `docker ps` 看一下真实名字。

**如果 ping 通了** → 跳到第二节。

**如果提示 `bad address` 或 `not found`** → 它们不在同一个网络，执行：

```bash
docker network connect snowluma_default astrbot
```

再 ping 一次。

> 这一步的意义：让 SnowLuma 能通过名字 `astrbot` 找到 AstrBot，
> 不用去记 IP。**IP 会变，名字不会。**

---

## 二、AstrBot 这边：开门

打开 AstrBot 控制台（`http://你的IP:43211`）。

1. 找到 **「消息平台」/「适配器」/「Platform」** 这一类入口
2. 点 **「新增」/「添加适配器」**
3. 类型选 **`aiocqhttp`**（界面上可能显示为 **「OneBot v11」**）

> 💡 这两个是同一个东西，只是名字不同，别被绕晕。

填这几项：

| 配置项 | 填什么 | 说明 |
|---|---|---|
| **反向 WS 主机** | `0.0.0.0` | 表示「接受任何来源的连接」 |
| **反向 WS 端口** | `6199` | 这就是那扇「门」 |
| **反向 WS Token** | 自己设一串密码，如 `tuhengyu2026` | **两边必须一致** |

保存，**启用**。

### 可以用命令行验证吗

其实这一步本质是改一个配置文件。如果你更喜欢命令行，
或者界面上找不到地方，可以连上服务器编辑它：

```bash
docker exec astrbot find / -name "cmd_config.json" 2>/dev/null
```

找到后用 `vi` 或 `nano` 编辑，在 `platform` 下面加：

```json
{
  "type": "aiocqhttp",
  "ws_reverse_host": "0.0.0.0",
  "ws_reverse_port": 6199,
  "ws_reverse_token": "tuhengyu2026"
}
```

> ⚠️ **这个文件带 BOM**（文件开头有几个看不见的字符）。
> 用程序读写的话要用 `utf-8-sig` 编码。用文本编辑器手动改不受影响。
>
> ⚠️ 改完要重启生效：`docker restart astrbot`

---

## 三、SnowLuma 这边：敲门

打开 SnowLuma 控制台（`http://你的IP:50507`）。

1. 找到 **「连接」/「OneBot」/「网络配置」** 这一类入口
2. 新增一个 **WebSocket 客户端**（可能叫 `wsClient`、`ws 客户端`）

填这几项 —— **⚠️ 每一项都要对，错一个字就连不上：**

| 配置项 | 填什么 |
|---|---|
| **名称** | `wsclient-1`（随便叫） |
| **目标 URL** | `ws://astrbot:6199/ws` |
| **访问令牌 / AccessToken** | `tuhengyu2026`（**和 AstrBot 那边一样**） |
| **角色 / Role** | `Universal` |
| **消息格式** | `数组` / `array` |
| **重连间隔** | `5000` |

### ⚠️ 三个最容易错的地方

1. **URL 末尾的 `/ws` 不能省。** 写成 `ws://astrbot:6199` 连不上。
2. **用容器名 `astrbot`，不是 IP 地址。** IP 会变，名字不会。
3. **Token 两边必须完全一致**（大小写、空格都算）。

填完，**点保存**。

---

## 四、验证：看两边的日志

保存后，立刻去两个地方看。

### ① SnowLuma 控制台

在 **「总览」** 或 **「OneBot 协议端点」** 里，`wsclient-1` 的状态应该变成
**「已连接」（绿色）**。

或者在左侧 **「日志」/「实时事件流」** 里，会看到类似：

```
[OneBot.WS-Client] [wsclient-1] connected ws://astrbot:6199/ws
```

### ② AstrBot 控制台

首页应该显示 **「QQ 在线」** 或 **「机器人上线」**。

日志里会有一行：

```
aiocqhttp(OneBot v11) 适配器已连接。
```

### 两边时间戳应该几乎一样

```
SnowLuma  12:43:44 [wsclient-1] connected ws://astrbot:6199/ws
AstrBot   12:43:44 aiocqhttp(OneBot v11) 适配器已连接。
```

**严丝合缝对上，就是真连上了。**

---

## 五、没连上怎么办

| 现象 | 可能原因 | 解决 |
|---|---|---|
| SnowLuma 一直「重连中」 | URL 写错 / 少了 `/ws` | 检查 URL |
| SnowLuma 报「连接被拒绝」 | AstrBot 那边没配好 / 没启用 | 回第二节检查 |
| SnowLuma 报「鉴权失败」 | Token 不一致 | 两边逐字符对一遍 |
| 两边都说连上了，但没握手 | 容器不同网络 | 重做第一节的 `docker network connect` |
| AstrBot 完全没反应 | 端口没监听 / 容器没重启 | `docker restart astrbot` 后重试 |

**排错时把 SnowLuma 的「日志」和 AstrBot 的日志对着看** ——
哪边先报错，问题就在哪边。

---

## 六、✅ 里程碑：链路打通

如果两边都显示已连接：

```
QQ ←→ SnowLuma ←(OneBot v11 WS)→ AstrBot
     ✓已登录      ✓已连接            ✓已连接
```

**这是整个项目的核心里程碑。**

但**现在给它发消息还不会有回复** —— 因为 AstrBot 还没接模型，
它不知道该说什么。
